# AGENTS.md

Homebrew tap `bgzo/hx`. Ruby formulae and casks only — no build/test toolchain beyond Homebrew itself.

## Repo layout

- `Formula/<name>.rb` — active formulae (currently contains only `sqlit`)
- `Casks/<name>.rb` — casks (currently contains `unigetui`; kept in sync via `brew bump-cask-pr`/livecheck)
- `.github/workflows/` — standard boilerplate generated by `brew tap-new`. Treat as canonical; don't rewrite.
- `.zed/` is gitignored local editor config.

## Workflow facts

- All formulae live in `Formula/`; deprecated/abandoned ones use the official `deprecate!` directive in the formula body (do **not** move files to a `Deprecated/` directory).
- Bottles are built by the `brew test-bot` workflow on PRs; after CI passes, `publish.yml` (`brew pr-pull`) merges the PR and commits bottles back to `main`. Merging a formula PR directly breaks the bottle flow.
- `autobump.yml` runs daily and opens version-bump PRs via `brew bump`.
- Commit messages use Conventional Commits with a formula scope: `feat(sqlit):`, `chore(formula):`, `docs:`.

## Python virtualenv formulae

sqlit is a `Language::Python::Virtualenv` formula: every dependency is a pinned `resource` block with exact URL + sha256, plus `virtualenv_install_with_resources`. When bumping versions, regenerate resource blocks with `brew update-python-resources --print-only <formula> <new-version>` and update the main `url`/`sha256` — a missed hash fails `brew audit` and CI.

## Testing

```bash
# full suite (same as CI)
brew test-bot --tap=bgzo/hx --only-tap-syntax
brew test-bot --tap=bgzo/hx --only-formulae

# quick single checks on a formula file
brew style <formula-file>
brew audit --strict <formula-file>
brew test <formula-file>   # runs the test do block
```

Note `brew test-bot` builds bottles and is slow; prefer `brew style`/`brew audit` for quick iterations. CI runs on macos-26 and ubuntu (homebrew/brew container).
